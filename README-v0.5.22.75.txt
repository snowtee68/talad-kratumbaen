V0.5.22.75 – Auto Rider Backend Repair
รวม V0.5.22.74 ทั้งหมดไว้แล้ว

Flow หลังแก้:
ลูกค้าสั่ง A+B+C
→ ร้านแต่ละร้านกดรับออเดอร์
→ ลูกค้าชำระ/แนบสลิปแต่ละร้าน
→ ร้านยืนยันรับเงิน
→ ถ้ายังมีร้านอื่นไม่ยืนยัน ระบบรอ
→ เมื่อร้านสุดท้ายยืนยันรับเงิน ระบบสร้าง Delivery batch ทันที แม้สินค้ายังอยู่สถานะ preparing
→ สร้างงานวิน 1 งานรวมทุก active shop
→ ส่ง Push ไปยังวินผ่าน send-rider-push
→ วินรับงาน ขณะที่ร้านเตรียมสินค้าได้ต่อ

จุดที่แก้:
- 22.68 เรียก market_create_delivery_batch() ซึ่งบังคับ status='ready'
  แต่ Auto Rider ต้องเริ่มตอน status='preparing' จึงไม่ทำงานจริง
- 22.75 สร้าง batch อัตโนมัติใน RPC ใหม่หลังตรวจครบทุกเงื่อนไข
- ล็อก group ป้องกันร้านสองร้านยืนยันพร้อมกันแล้วสร้างงานวินซ้ำ
- ถ้า batch อยู่ creating จากความล้มเหลวก่อนหน้า ระบบ resume ได้
- finish RPC เป็น idempotent ป้องกันสร้าง rider job ซ้ำ
- ไม่สร้างวินแยกร้านอัตโนมัติ: รอทุก active shop เพื่อค่าส่งเที่ยวเดียว
- ร้านที่ cancelled จะไม่ถูกนับเป็นร้านที่ต้องรอ
- หน้า Customer ไม่เสนอ “ส่งร้านที่พร้อมก่อน” อีกแล้ว
- ปุ่ม manual เปลี่ยนเป็น fallback “ตรวจสอบ/เรียกวินอีกครั้ง” และจะใช้ได้เฉพาะเมื่อทุกร้านพร้อม
- ค่าวินยังเป็น COD ปลายทางเหมือนเดิม
- Push rider เดิมจาก 22.66 ยังทำงานต่อ

ทดสอบ:
1) สั่ง Delivery 1 ร้าน
2) ร้านรับ order
3) ลูกค้าแนบสลิป
4) ร้านกด “เงินเข้าแล้ว / เริ่มเตรียม”
5) ต้องเกิดงานวินทันทีโดยไม่ต้องกดเรียกวินเอง
6) หน้าวินต้องเห็นงาน + ได้ Push (หากเปิดสิทธิ์ไว้)

Multi-shop:
A+C ยืนยันแล้ว แต่ B ยังไม่ยืนยัน/ยังไม่รับ order → ยังไม่เรียกวิน
B ถูกยกเลิก → ระบบไม่นับ B
เมื่อ active shops ที่เหลือยืนยันครบ → เรียกวินรวมเที่ยวเดียว
